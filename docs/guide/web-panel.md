# The Mainsail and Fluidd panel

## What it is and why

The same views as the display, drawn in the browser as a panel in Mainsail or
Fluidd. It is a Vue 2 component set (`web/vue`) over a TypeScript twin of the
core (`web/logic`). The panel draws the view tree the core returns. It reads no
printer object and composes no text; every string is the core's, so the
display and the panel say the same thing in the same language.

## What it adds

- The unit, toolhead, bays and alerts on the dashboard, with no extra device.
- Spool editing as a form (the same call as the display's).
- On the standalone page, the host's settings and language in one popover.
- Host look: the panel uses the host's card, font and status colors, and keeps
  filament colors fixed.

## Install the ready-made Mainsail

Mainsail users need no build. The OpenAMS build of Mainsail
([OpenAMSOrg/mainsail](https://github.com/OpenAMSOrg/mainsail)) is Mainsail
with this panel, generated by `tools/gen_host.mjs`. On the printer, with
OpenAMS installed in `~/openams`:

```sh
~/openams/install.sh --mainsail-panel
```

It downloads the latest release, keeps your Mainsail settings and the Mainsail
you had (as `~/mainsail.stock`), and points Moonraker's
`[update_manager mainsail]` at OpenAMSOrg/mainsail, so Mainsail's own update
button keeps the panel. A Mainsail that is a link or a git checkout is left
alone. `~/openams/install.sh -u` puts the stock Mainsail back.

The rest of this page is for building the panel into a Mainsail or Fluidd of
your own.

## Requirements

- A Mainsail or Fluidd checkout you build yourself. The panel is generated as
  source into the checkout and ships with your build of that host.
- Node.js, to run the generator and the host's own build.
- The OpenAMS plugin on the printer, as for the display.

## Install

The generator is `tools/gen_host.mjs`. It writes the panel folder, the host
wrapper and a small patch into the host (an icon, a locale string, a
dashboard entry), then formats the output with the host's own tooling.

```sh
node tools/gen_host.mjs --list                                  # the hosts it knows
node tools/gen_host.mjs --host mainsail --out <mainsail checkout>
node tools/gen_host.mjs --host fluidd   --out <fluidd checkout>
```

| Host | Panel folder written | Entry file |
|------|----------------------|------------|
| `mainsail` | `src/components/panels/Openams` | `src/components/panels/OpenamsPanel.vue` |
| `fluidd` | `src/components/widgets/openams` | `src/components/widgets/openams/OpenamsCard.vue` |

Then build the host as you normally do and deploy it. Do not hand-edit the
generated files: the next run overwrites them.

To see what would be written without writing it, add `--list` after `--host`.
To check that a checkout still matches the source (it exits 1 and names the
differences if not):

```sh
node tools/gen_host.mjs --host mainsail --out <mainsail checkout> --check
```

`--no-hook` skips the host patch, for a scratch directory that is not a
checkout.

## Configure the essentials

There is little to configure. The panel takes its data from the host's
existing Moonraker socket, so no address or key is entered. The standalone
page has its own bar with a settings popover (the host's switches and the
language). Themes follow the host; a standalone page takes a
`theme` of `dark` or `light`.

## What the controls do

Each bay is a tile. Its click targets (`docs/design/UNIFIED_UI.md`, section 4b):

| Target | Does |
|--------|------|
| The ring | opens the spool's editing: color, group, Spoolman spool |
| The tag (Not inserted, Error, Runout, Positioning) | opens its details |
| The tool pill (`T0`, with `∞n` for a spare) | changes the bay's group ("Change group...") |
| The rest of the tile | loads or unloads that spool |

- **Ring:** the arc is the remaining filament; its text is the core's. A bay
  with no spool has no ring, but its place stays reserved.
- **Tag:** drawn over the ring, red for an error, yellow for information, gray
  for a plain state. A tag hides the percentage while it shows.
- **Tool pill:** shows the group. The spare badge counts spares: a bare `∞` on
  the loaded member, `∞1`, `∞2` on the others in order.
- **Alerts:** one per level. OpenAMS-wide alerts go in the host's bar, a
  toolhead's at the top right of its card, a unit's at the right end of its
  header. The badge is red for a fault or pause, yellow otherwise.
- **Humidity reading:** click it for the drying and heating menu.

Actions open in a popover anchored to their source. A form or a confirm opens
the panel's one dialog (a native `<dialog>`, so focus and Escape just work). A
confirm appears only for a drastic action and is shown as the core wrote it. A
form's button stays dead until a field differs from where it opened. A refusal
from the host appears as a notice with the host's words.

## Check that it works

Open the host's dashboard. An "OpenAMS" panel (title from the locale string the
patch adds) should appear once Klipper is ready, showing your toolheads and
units. With no units it says "No OpenAMS units are connected."

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| No panel on the dashboard | Klipper not ready, or patch not applied | check Klipper's state; run `--check` |
| `--check` reports differing files | the checkout changed since generation | rerun without `--check` |
| `unknown host: ...` | typo | use a name from `--list` |
| `--out is not a directory: ...` | wrong path | point at the checkout root |
| "No OpenAMS units are connected." | plugin not publishing units | see the plugin's docs |

## Update and uninstall

Update: pull the display repository and rerun the generator, then rebuild the
host. It prunes files it no longer writes. Uninstall: revert the generated
folder, the entry file and the hook patch in your host checkout (the patch is
`web/hosts/<host>/hook.patch`; `git checkout` of those paths is the simplest
way).

## Gotchas

- Generated files are source in your fork but belong to the generator: a
  rerun overwrites hand edits.
- Filament colors never follow the theme; everything else does.
- A unit with more than four lanes (an EMU with five or more) is not laid out
  yet.
